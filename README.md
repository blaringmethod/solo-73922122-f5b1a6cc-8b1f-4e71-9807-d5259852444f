# 风电限发损失归因入仓

Flask + SQLite 网页应用：导入一台风机的 15 分钟计量表（UTC 时刻、可发量、实发量），
录入/更正限发单，按日核算各原因损失与“待查”电量。

## 启动

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000>。SQLite 数据存放在命名卷 `curtailment-data`
（容器内 `/app/instance/curtailment.sqlite3`），重启容器不丢数据。

本地不用 Docker 时：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 8 'curtailment.app:create_app()'
# 或 python -m curtailment（Flask 开发服务器，勿用于生产）
```

环境变量：`CURTAILMENT_DB`（数据库路径）、`CURTAILMENT_SECRET`（会话密钥，部署前务必修改）、
`HOST`/`PORT`（`python -m curtailment` 时生效）。

## 计量表 CSV

带表头（推荐），列名可用中文或英文：

```csv
时刻,可发量,实发量
2026-01-01T00:00:00Z,10.0,4.0
2026-01-01T00:15:00Z,12.5,4.0
```

- 时刻用 ISO 8601；带时区的会换算到 UTC，不带的按 UTC。必须对齐 15 分钟。
- 可识别列名：`时刻/时间/utc时刻/time/timestamp`、`可发量/可发/理论可发量/available`、
  `实发量/实发/实际发电量/actual`，可另加 `风机/机组/turbine` 列。
- 无表头的三列文件按 `时刻, 可发量, 实发量` 解析（四列时第 4 列为风机）。
- 一个文件只能是一台风机；重复导入同一 (风机, 时刻) 会覆盖原值。
- 补传/合并导入按格比对：**只有新增、改值或删去的格**参与超限复核与重算；
  值未变的格共用原计量记录，不重写、不复核。
- `实发量 > 可发量` 的格会提示并按无损失处理。

## 规则

1. 计量表按 15 分钟一格；单据覆盖满足 `开始 <= 格时刻 < 结束`（结束为开区间）。
2. 同一格同一原因有多张单时，取**最低上限**；不同原因各自保留最低上限。
3. 在 `[实发量, 可发量]` 之间用该格所有上限切段；每一段均分给
   “上限**不高于该段下端**”的所有原因（每个原因每段至多一份）。
4. 没有原因认领的段计入**待查**，页面按日列出待查电量与待查格。
5. 任一覆盖格 `实发量 > 每格上限` 即冲突：新建/更正时**整单退回**，页面列出冲突格与单号，
   提交失败时原单据与归因结果都保持不变。
6. 导入计量后，覆盖本次变化格的既有单据按**变化格**复核（长期单也只复核这些格，
   不重扫整段历史）；出现超限则**整单暂停**，其覆盖的损失落为待查。
   单据详情按**风机编号 + UTC 时刻**列出全部超限格；同一时刻两台风机各保留一格。
   整单所有超限格消除后才恢复参与归因。
7. 单据提交（含同号更正）与归因结果同一事务生效；新建/更正会扫描该单
   （更正含新旧两段）覆盖时段的计量格做冲突检查，并重算覆盖时段内各风机日报。
8. 暂停/恢复、计量变化、日报与超限明细在同一事务里生效；任一步失败整体回滚。
   重算按（风机, UTC 日期）范围进行，不逐格落库。
9. 结果量化到 0.001 kWh；每格保证 `各原因损失 + 待查 = 可发量 − 实发量`（最大余数法分摊尾差）。

旧库升级后首次启动会自动做一次扫描：为既有单据补建超限明细、重判暂停状态、
重算受影响日报；之后一律走增量。新库首次启动直接跳过。

### 演示：网页补传后逐个消除超限

1. 首页导入 `samples/meter-WT-001-2026-01-01.csv`（风机填 `WT-001`）。
2. 在“限发单”页新建一张 `2026-01-01T00:00:00Z`–`2026-01-01T02:00:00Z`、
   每格上限 `4` 的单，例如 `CUR-001`（全风场口径）。
3. 再导入 `samples/backfill-WT-001-2026-01-01.csv`：只有 00:00、00:15 两格改值且超限。
   导入提示会写明“复核 2 个变化格 / 单据 CUR-001 复核 2 格”，单据随即整单暂停，
   单据详情按风机 + UTC 时刻列出这两个超限格，日报损失落待查。
4. 补传合规值（如 `00:00` 实发 `4.000`），超限格减为 1；再补 `00:15` 实发 `4.000`，
   超限格清零，单据自动恢复，日报损失回来。

每次补传只会复核发生变化的格；短期单与长期单各自只复核与自己覆盖时段重叠的变化格
（例如同一份 96 格补传：2 小时单复核 8 格，24 小时单复核 96 格）。

## 目录

- `curtailment/allocation.py` — 纯计算：分段、归因、冲突检查
- `curtailment/parsing.py` — 时刻/CSV 解析
- `curtailment/service.py` — 导入、单据、重算、查询
- `curtailment/app.py` — Flask 路由
- `templates/`, `static/` — 页面
- `samples/` — 示例计量 CSV（`meter-…` 为整日计量，`backfill-…` 为补传 4 格）
- `tests/` — pytest（71 项）

限发单没有风机字段，按**全风场口径**处理：一张单对其覆盖时段内所有风机的计量格都生效；
冲突检查也针对这些格。
